# RAG Bad Case 分析

以下案例来自 2026-06-24 的 Qwen3-4B + QLoRA 与 DeepSeek V4 Pro 双模型实验，均使用 `hybrid_reranker` 设置。

| Case | 失败位置 | Qwen 表现 | DeepSeek 表现 | 主要原因 |
|---|---|---|---|---|
| 1 | 三花智控业绩预告检索 | 使用其他公司的净利润区间作答 | 明确说明未检索到三花智控 | 公司主体和公告类型过滤不足 |
| 2 | 天赐材料原因分析检索 | 根据其他公司经营因素生成答案 | 拒绝基于错误主体作答 | 原因类问题语义宽泛，主体错配 |
| 3 | 启迪设计减值准备生成 | 输出错误事件类型和损坏 JSON | 正确提取两类减值准备及金额 | QLoRA 输出模板与当前 Prompt 不一致 |
| 4 | 第四季度财务数据 | 复制表格碎片，未给出目标数字 | 明确说明证据不足 | 需要表格结构化抽取或季度差额计算 |
| 5 | 投资建议拒答 | 会出现“不构成投资建议”，但结构化输出较混乱 | 2/4 个问题没有直接声明不能提供交易建议 | 应在 Pipeline 中硬短路拒答 |

## Case 1：三花智控主体未命中

- 问题：三花智控预计2025年度归母净利润区间是多少？
- Qwen：引用其他公司业绩预告中的数字并生成答案。
- DeepSeek：识别到五条证据均不属于三花智控，回答“仅凭当前资料无法判断”。
- 两者 `context_recall=0.0`，说明根因在检索层，而不是生成层。
- 改进：从问题抽取公司名、股票代码和公告类型，在 Dense/Hybrid 检索后增加主体硬过滤。

## Case 2：天赐材料原因分析主体错配

- 问题：天赐材料盈利能力提升还受到哪些经营因素影响？
- 实际召回主体包括其他上市公司，没有天赐材料。
- Qwen 会根据语义相似片段继续生成经营原因；DeepSeek 会指出主体不一致并拒绝推断。
- 改进：增加公司实体过滤、公告类型过滤和面向原因问题的 query rewrite。

## Case 3：Qwen 输出格式损坏

- 问题：启迪设计2024年计提了哪些较大金额减值准备？
- Qwen：误判成“利润分配/分红”，并产生嵌套、未闭合的 JSON 文本。
- DeepSeek：正确回答信用减值准备 16,085.80 万元、资产减值准备 9,936.97 万元。
- 改进：统一 QLoRA 训练格式与 RAG Prompt；增加 JSON Schema 或结构化输出校验。

## Case 4：季度表格计算能力不足

- 问题：启迪设计2024年第四季度营业收入和归母净利润是多少？
- Qwen：大量复制所有者权益和财务表碎片。
- DeepSeek：没有在证据中找到第四季度独立数据，因此拒绝编造。
- 改进：解析财务表字段，建立年度、前三季度、第四季度的结构化计算链路。

## Case 5：投资建议拒答不够稳定

- 问题包括“应该加仓吗”“能不能建仓”“是不是应该卖出”。
- 当前代码会清空引用，但仍把问题交给生成模型。
- Qwen 常以“不构成投资建议”结尾，但主体内容仍可能是混乱的公告模板。
- DeepSeek 对部分问题只回答“资料不足”，没有直接强调不能提供交易建议。
- 改进：识别到投资建议意图后，由 `RAGPipeline` 直接返回统一拒答，不再调用生成模型。

规则指标仅用于快速比较，不能替代人工评审或 RAGAS。尤其是单位换算、同义表达和拒答语义可能被关键词规则低估。
